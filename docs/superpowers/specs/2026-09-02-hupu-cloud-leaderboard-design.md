# 虎扑云端排行榜设计

## 目标

为《一指登塔：灰烬回廊》增加跨玩家共享的虎扑排行榜，同时保留离线游玩和本地存档能力。排行榜使用虎扑账号昵称展示，普通冒险和每日挑战都参与排名。

## 已确认规则

- 排行榜跨玩家共享。
- 昵称使用虎扑账号昵称，不提供独立昵称输入。
- 普通冒险成绩纳入历史总榜。
- 每日挑战按挑战码分榜。
- 总榜取玩家历史最高成绩。
- 每日榜取玩家当天该挑战码最高成绩。
- 分数相同按通关用时更短者优先，再按提交时间更早者优先。
- 本地存档继续保存完整游戏进度，云端只保存排行榜所需数据。
- 网络不可用不阻塞游戏；成绩进入待同步队列，恢复网络后自动重试。

## 用户流程

1. 玩家使用虎扑账号进入游戏。
2. 玩家进行普通冒险或每日挑战。
3. 结算页展示本地成绩，并尝试提交云端排行榜。
4. 提交成功后显示同步状态和当前排名；失败则显示本地待同步提示。
5. 大厅进入“排行榜”页面，查看每日榜、历史总榜和自己的排名。

## 页面设计

新增排行榜入口和排行榜页面：

- 标签切换：每日挑战 / 历史总榜。
- 排名列表：名次、虎扑昵称、分数、层数、用时、武器。
- 当前玩家高亮。
- 我的排名、最高分、最快通关摘要。
- 加载中、空榜、网络失败、未登录状态。
- 移动端竖屏布局，列表不产生横向滚动。

## 数据边界

上传字段限定为：

- 账号稳定标识（仅用于服务端归属，不在页面展示）。
- 虎扑账号昵称。
- 分数、通关层数、通关时间、武器。
- 模式、挑战码、挑战日期、是否通关 50 层。
- 提交时间和客户端规则版本。

不上传手机号、设备文件、完整本地存档或无关浏览记录。

## 云端接口约定

前端通过虎扑提供的云端请求能力访问后台，不手写鉴权令牌或直接拼接 Bearer 请求。后台复用活动已有 API 基线，提供：

- `GET /api/leaderboard/list?scope=daily|all&code=<challenge-code>`：读取榜单。
- `GET /api/leaderboard/me?scope=daily|all&code=<challenge-code>`：读取当前玩家排名。
- `POST /api/leaderboard/submit`：提交成绩，服务端校验后写入。

服务端按账号和榜单范围做唯一归属，重复提交只保留更优成绩。公开读取不暴露账号稳定标识。

## 计分与防作弊

- 服务端根据楼层、敌人、Boss、生命、金币、通关和速度字段重新计算分数。
- 校验模式、挑战码、武器、楼层上限、通关时间和统计字段范围。
- 每日挑战必须匹配当天有效挑战码。
- 客户端显示的分数不能直接决定排名。
- 异常或重复请求返回可理解的失败原因，游戏本地流程继续。

## 离线与同步

- 本地 IndexedDB/localStorage 继续作为游戏进度事实源。
- 排行榜提交失败时，将待同步记录写入本地队列。
- 页面重新打开、网络恢复或结算后触发有限次数重试。
- 同一记录使用稳定提交键避免重复写入。
- 云端成绩读取失败时展示最近一次本地缓存榜单（若存在）并标注时间。

## 错误处理

- 未登录：允许继续单机，排行榜显示登录提示。
- 网络失败：不阻塞结算，不丢失本地成绩。
- 接口校验失败：保留本地记录并提示成绩未同步。
- 榜单为空：显示活动尚未产生排名的状态。
- 云端返回异常数据：丢弃异常行，保留页面可用性。

## 测试范围

- 分数服务端重算与非法字段拒绝。
- 每日榜和总榜的排序、去重和同分规则。
- 普通冒险进入总榜，每日挑战进入对应挑战码榜单。
- 离线提交入队、恢复网络后重试、重复提交幂等。
- 未登录、接口失败、空榜和异常响应的 UI 状态。
- 手机 390×844 视口下无横向溢出，排行榜可滚动查看。

## 不在本阶段范围

- 排行榜奖励、赛季结算和实物奖品。
- 公开展示账号头像、手机号或其他个人资料。
- 修改现有战斗数值、武器、Boss 和 50 层内容。
- 强制联网或阻止游客离线游玩。
