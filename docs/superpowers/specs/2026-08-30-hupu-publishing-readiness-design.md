# 虎扑发布资格版设计

## 目标

将《一指登塔：灰烬回廊》从可玩的离线原型完善为可演示、可提交审核的手机竖屏 H5 版本。首阶段不依赖虎扑私有接口、账号系统或广告网络；获得开发者资格后，通过适配器替换外部能力。

## 首阶段范围

- 50 层主线流程可从开始挑战走到失败或通关结算。
- 五个章节拥有独立背景、三种章节小怪和一个章节 Boss。
- 层数、路线、精英战、事件、商店、强化、回血、Boss 机制和深渊入口可连续运行。
- 结束页提供重新开始、返回大厅和成绩分享。
- 分享生成游戏名、模式、层数、武器、Boss 数、用时和成绩文案；优先使用系统分享，失败时复制文本并打开虎扑入口。
- 失败结算提供每局一次的“观看广告复活”演示流程。演示流程不联网、不发放真实广告收益，奖励只在模拟观看完成后发放。
- 首次游玩提供简短的新手引导，可在设置中关闭或重新查看。
- 50 层难度使用章节和路线差异化曲线，三种武器都能在合理构筑下完成主线。
- 设置页显示音效、震动、减少动态效果、引导开关和版本信息。
- 发布说明包含本地存档、隐私、资源来源和反馈入口，不收集账号或设备数据。

## 外部能力适配

```text
ShareAdapter
├─ WebShareAdapter       系统分享
├─ ClipboardShareAdapter 复制文案并打开虎扑入口
└─ HupuShareAdapter       获得官方权限后接入

RewardAdAdapter
├─ DemoRewardAdAdapter   当前离线演示
└─ HupuRewardAdAdapter   获得广告 SDK 后接入
```

游戏逻辑只依赖 `share(text, context)` 和 `showRewardedAd()` 两个异步接口。外部接口不可用、用户取消或网络失败时，游戏显示可理解的失败提示，不发放奖励。

## 复活规则

- 仅失败结算时显示复活入口。
- 每局最多成功复活一次，状态保存在运行状态而非永久存档。
- 复活恢复 35% 最大生命值，并获得 2 秒无敌或减伤保护。
- 复活后返回当前战斗，不重新生成敌人、不重置路线和强化。
- 主线、深渊和每日挑战均遵守次数限制；每日挑战的复活规则固定，避免同码成绩因广告状态产生不一致。

## 50 层内容与平衡

- 第 10、20、30、40、50 层为章节 Boss 层。
- 普通层按章节敌池生成，左路增加敌人数和奖励，中路保持标准，右路减少敌人数但奖励降低。
- 每章后半段提高精英概率和敌人组合复杂度，生命与攻击增长保持连续。
- Boss 至少拥有两个生命阶段和一个可预警技能；预警区域、伤害区域和召唤物必须在手机屏幕上清晰可见。
- 通过脚本测试检查楼层数据完整性、Boss 映射、敌人池切换和数值单调性；通过浏览器实测检查三种武器在主线中可玩。

## 存档与异常处理

- 继续使用现有 localStorage + IndexedDB 双写存档。
- 结算、升级、成就、图鉴、复活使用后的状态变化立即保存。
- 导入存档前校验版本、字段类型和范围；坏数据只拒绝导入，不覆盖当前存档。
- 页面刷新或关闭不恢复进行中的战斗，避免重复奖励；下一次进入从大厅开始。
- 任何奖励发放函数必须具备幂等保护，防止重复点击。

## 发布验收

- 390 x 844 竖屏无横向滚动，主要按钮点击区域不小于 44 x 44 px。
- 首次打开可在无网络状态进入主菜单并开始普通冒险。
- 能完成至少一轮失败结算和一轮通关结算。
- 分享取消、剪贴板不可用和虎扑未安装时仍有可用回退路径。
- 复活演示取消或失败不改变生命和余烬；成功只生效一次。
- 控制台无未处理异常，Service Worker 缓存包含新增脚本和样式。
- Android/iOS 常见竖屏浏览器及虎扑内置浏览器完成手动检查。

## 后续阶段

获得虎扑开发者资格后，仅替换分享和广告适配器，保留游戏核心逻辑、存档结构和离线回退能力。任何官方接口都必须增加权限缺失、用户拒绝、网络超时和版本不兼容处理。
